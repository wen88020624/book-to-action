---

## 一句話

把書裡的方法論變成**可立刻在生活中實踐、可追蹤、可判斷適不適合自己**的互動體驗——解決「讀很多書，生活卻毫無實際改善」的困境。

---

## 我們要解決的問題

很多人讀完書只有「懂了」的感覺，卻缺少：

1. **從概念到行動的橋** — 方法論停在筆記裡，沒有可執行的下一步
2. **低摩擦的導入** — 不知道怎麼把書裡的步驟嵌進自己的日常
3. **誠實的回饋迴路** — 無法在短時間內知道「這套方法適不適合我」

因此價值單位不是「書」或「閱讀進度」，而是：**一次可驗證的生活實驗（Experiment）**，以及未來可復用的**方法論模板（Methodology Template）**。

---

## North Star 核心循環

```
書 / 平台模板
    ↓
方法論（可互動、可執行的說明與引導）
    ↓
立刻在生活中實踐（Experiment）
    ↓
紀錄發生了什麼（Log）
    ↓
快速知道「適不適合我」（Result + Rating）
```

成功指標（概念層，非 KPI 儀表板）：

- 從「理解概念」到「開始實踐」的時間要短
- 使用者能誠實回答：這套方法對我有幫助 / 部分有 / 沒有 / 還不知道
- 避免「收藏很多書、零行動」的結果

---

## 內容進入方式（雙軌）

光「導入書」就有很多路徑；也不一定要使用者自己貼全文。

| 軌道 | 說明 | 狀態 |
|---|---|---|
| **A. 使用者導入** | 使用者新增書 → 擷取／整理書中方法論 → 變成可互動的實踐流程 | MVP 已有「書 → Concept → Experiment」雛形；「方法論互動 Web / 全文導入」延後 |
| **B. 平台上架模板** | 平台方整理好方法論模板，使用者直接套用開始實驗，不必自己導入文字 | **下一階段優先（路徑甲）** — 細節收斂中 |

兩軌最終都匯入同一套：**Experiment → Log → Result**。  
書只是來源之一；模板、跨書合成的方法論也可以是來源。

### 收斂中的決策

| 主題 | 現況 |
|---|---|
| 下一階段優先路徑 | ✅ **路徑甲**：打開 App → 選現成模板 → 立刻開始實驗 |
| 路徑乙（使用者貼方法論／自己導入） | 延後；不阻擋路徑甲 |
| 誰產生模板 | ✅ **平台先產**現成書本練習模板；使用者引入實驗後可編輯 |
| 模板裡有什麼 | ✅ 書中既有的**練習／實驗結構**（可含表格等結構化內容），引入後變成可編輯的 Experiment |
| 「互動」長怎樣 | ✅ **就是現有 Experiment 循環**；差別在內容形態可超越純文字（例如表格紀錄） |
| 付費／進階（非下一階段必做） | 📌 上傳書 PDF，或「人生現況／問題 + 既有模板」打 LLM 產出個人化實驗，再微調 |
| 與 Concept 的關係 | ❓ 未決（模板是否仍經過 Concept，或直接 → Experiment） |
| 第一批誰上架、上幾套 | ❓ 未決（例：原子習慣練習室） |

### 模板 → 實驗（已對齊的行為）

```
平台模板（來自書中練習）
    ↓ 引入
Experiment（可編輯副本，不鎖死模板原文）
    ↓
紀錄（可為 freeform Log，或結構化內容如表格）
    ↓
Result + Rating（適不適合我）
```

**範例：**《原子習慣》練習室「每小時練習紀錄」→ 模板帶一張表格 → 使用者引入後在實驗裡填表、可改欄位／說明。

### 分層：現在 vs 之後

| 層 | 內容 | 何時 |
|---|---|---|
| **L1 平台模板** | 人工整理的書本練習模板 → 引入 Experiment → 可編輯；內容可含表格等 | **下一階段優先** |
| **L2 個人化生成（付費方向）** | 上傳 PDF，或「現況／問題 + 模板」→ LLM → 個人化實驗項目 → 微調 | 之後；不阻擋 L1 |

### 軌道 A 的可能形態（尚未全部實作）

- 只填書名（現行 MVP）
- 貼上書中某段方法論說明 → 結構化成步驟／檢查清單／引導問題
- 匯出／匯入方法論草稿（未來）
- AI 輔助擷取（**明確非 MVP**；方向上可討論，實作需另開 Phase）

### 軌道 B 的可能形態（尚未實作）

- 平台策展的「書本練習模板庫」（L1）
- 引入後成為 **可編輯的 Experiment 副本**（非唯讀課件）
- 實驗內容區塊：至少支援說明文字 + **表格**（如時段練習紀錄）；可再擴充其他結構
- 模板可標註來源書，但不強迫使用者先建 Book
- （L2／付費）PDF 或「現況 + 模板」→ LLM 生成個人化實驗 — 見上方分層

## 與現行 MVP 的關係

| 層級 | 現行 MVP（見 SPEC） | North Star / 下一階段 |
|---|---|---|
| 輸入 | Book（title only）+ 使用者自寫 Concept | **平台練習模板**（L1）；之後 PDF／LLM 個人化（L2） |
| 中間產物 | Concept（「我吸收了什麼」） | 模板可直接 → Experiment（Concept 是否保留：未決） |
| 行動 | 手動建立 Experiment | 從模板**引入**可編輯 Experiment |
| 追蹤 | Freeform Log | Freeform **或結構化內容（表格等）**，仍掛在 Experiment 上 |
| 結果 | Result + helpfulness rating | 同左——快速判斷適不適合自己 |

**設計原則不變：**

1. Experiments first — 首頁先看進行中的實驗，不是書架
2. Zero-friction logging — 紀錄越簡單越好
3. 「我吸收了什麼」優於「書上怎麼寫」
4. 誠實結果 —「還不知道」是合法且可永久保留的答案
5. No judgment — 不問「你成功了嗎？」、不秀失敗排行

## 產品邊界（持續有效）

### 我們是

- 閱讀 → 行動的轉換器
- 生活實驗追蹤器
- （未來）方法論模板平台

### 我們不是

- 讀書管理／書庫 App（ISBN、封面、進度條不是核心）
- 打卡／連續天數激勵工具
- 社交動態或書評社群（至少非近期）

---

## 給 AI 的決策啟發式

實作或提議功能前，問：

1. 這是否縮短「理解 → 開始實踐」？
2. 這是否讓人更容易追蹤並判斷「適不適合我」？
3. 這是否讓 Book／模板服務 Experiment，而不是反過來？
4. 若只對「收藏書」有幫助、對實驗無幫助 → **不做或降優先**
